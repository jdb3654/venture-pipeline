## What the native tests establish

OEE's shipped example rows have equal planned times, so matching their arithmetic
average cannot prove time weighting. A separate 60-minute/240-minute example
has expected 90% OEE (270 ideal-good minutes / 300 planned minutes), versus 75%
if percentages were averaged. The diagnostic lane tests this independently.
Dashboard time/count sums and blank/from/to/both/boundary/outside date selections
are checked separately from percentages, so some raw sums pass while unsupported
IFERROR makes dependent percentages fail.

Correct heterogeneous OEE sums each row's ideal **good** time. For two equal
60-minute machines, Slow (60-second cycle, 60 good of 60) and Fast (6-second
cycle, 0 good of 600), correct total is 60 ideal-good / 120 planned = 50%; the
diagnostic native total is 9.0909%. The shipped examples independently expect
79.3835227273%, while the diagnostic formula yields 79.3865181536%.
The delivered
all-machine formula instead uses summed ideal total time multiplied by a single
good-parts fraction. Those expressions are equal only under additional conditions
(such as common ideal cycle time or equal reject fractions), neither promised
by this multi-machine product. [OEE calculation](https://www.oee.com/calculating-oee/)
uses good count × ideal cycle time / planned production time; this is a commercial
Vorne methodology source, not evidence of customer demand.

Downtime durations are independently calculated, including 23:40–00:25 = 45
minutes, midnight, zero-minute override and missing endpoints. A selected literal
machine lets ranking/tie/30-reason/cumulative tests run independently of the
blank-filter defect. Its top-12 chart can correctly stop below 100% when more
than 12 reasons exist; the complete table's last positive row must reach 100%.
Unknown-reason loss and inconsistent stop definitions are separate defects.

PM tests compare all three status counts to an independent count of the 300 plan
rows. Dates use the host date recorded in results. Relative TODAY()-N examples
keep approximately the same demonstration statuses after weeks, deliberately;
these are not historical completion dates. The new guide correctly discloses
that. Buyers must clear examples and enter real dates for their own tasks.

Every native scenario is scanned for formula errors across all sheets, including
empty preallocated formula rows. An error exported as a null value is a FAIL,
not a successful missing-input warning. Invalid-input suppression assertions are
the review's acceptance recommendation: where the product chooses to display a
diagnostic number, it should visibly exclude or label invalid rows rather than
present them as trustworthy OEE.

The exported files contain no `_xlfn`/`_xlws` modern-function prefixes. Function
availability is supported by Microsoft's [function catalog](https://support.microsoft.com/en-us/excel/excel-functions-alphabetical)
and [performance guidance](https://learn.microsoft.com/en-us/office/vba/excel/concepts/excel-performance/excel-tips-for-optimizing-performance-obstructions)
(SUMIFS/COUNTIFS introduced in 2007). The exact formulas' results in Excel,
particularly SUMPRODUCT(MAX(array multiplication)), have **not** been verified.

All nine conditional rules are formula rules, using legacy AND/ISNUMBER and
comparisons: OEE Q5:Q504 and Dashboard K9:K29 each have `>=target`,
`>=0.6 and <target`, `<0.6`; PM I5:I304 compares status with OVERDUE, Due soon,
OK. Cross-sheet OEE target references are supported in Excel 2010 according to
this dated [Microsoft support example](https://learn.microsoft.com/en-us/answers/questions/4857317/conditional-formatting-based-on-performance-in-a-r).
Confidence in feature availability is high, in imported rendering moderate.
With a target below 60%, green and red rules can overlap for a value between
target and 60%; constrain target or define precedence. This boundary needs an
additional native visual regression before making arbitrary-target claims.

All seven validation definitions: OEE machine C5:C504, numeric D5:H504;
downtime machine C5:C1004, reason H5:H1004, filter B5; PM asset B5:B2004,
task C5:C2004. These are ordinary
list/nonnegative-decimal validation with allowBlank; every error message is
disabled. Direct references to another sheet in the same workbook are supported
in Excel 2010 per the [2011 Microsoft support answer](https://learn.microsoft.com/en-us/answers/questions/3a8b154a-49a3-4d54-b055-45548c6fb270/excel-2010-drop-down-list-data-from-another?forum=msoffice-all).
Availability confidence high; user interaction and error enforcement unverified
in Excel. This is not a dependent asset/task dropdown: each PM list is independent.

Charts: OEE vertical column; downtime vertical columns plus unsmoothed line,
secondary value axis id 200 with range 0–1 and 0% labels; PM none. These are
legacy Excel chart features ([Microsoft chart types](https://learn.microsoft.com/en-us/office/vba/api/excel.xlcharttype),
[Excel 2010 secondary-axis example](https://learn.microsoft.com/en-us/answers/questions/4879957/excel-add-a-vertical-line-to-a-stacked-bar-chart-%28)).
Feature support confidence high; the specific exported OOXML combo and caches
on Excel 2010 remain unverified. Freeze panes are standard supported features.
The minimum version is plausible structurally, but “Requires Excel 2010 or later”
is a **compatibility promise not proved by this review**.

Excel criteria use `*` for any sequence, `?` for a character and `~` as escape:
[SUMIFS](https://support.microsoft.com/en-au/excel/functions/sumifs-function),
[wildcards](https://support.microsoft.com/en-us/excel/using-wildcard-characters-in-searches).
Exact-mode [MATCH](https://support.microsoft.com/en-us/excel/functions/match-function)
also accepts wildcards in text lookup values; the cycle/category lookups require
the same treatment, not just SUMIFS/COUNTIFS.
Escape literal tilde first, then asterisk and question mark, consistently in
all matching formulas, or use actual equality. New OEE/downtime guides advise
avoiding these in machine names; they do not constrain reason names or enforce
the restriction. Imported AOO Regex=False explains why a native literal-name
test can pass while the Excel structural check fails. AOO's
[condition semantics](https://wiki.openoffice.org/wiki/Documentation/AOO4_User_Guides/Calc_Guide/Calc_As_A_Simple_Database/Calc_Functions_Similar_to_Database_Functions/Count_and_Sum_Cells_that_Match_Conditions_COUNTIF_COUNTIFS_SUMIF_SUMIFS_and_SUMPRODUCT)
are not interchangeable with Excel wildcards.
